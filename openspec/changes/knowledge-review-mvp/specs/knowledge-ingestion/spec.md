# Spec Delta

## Purpose

把用户发来的原始知识文本，经大模型整理为结构化的「课程 + 卡片」，并持久化到本地 JSON 文件。它负责收件与加工之间的解耦，使白天随时收集与夜间集中处理互不阻塞。

## ADDED Requirements

### Requirement: 知识入队

系统 SHALL 将收到的知识文本先存入待处理队列，MUST NOT 在收到时刻立即调用大模型。

#### Scenario: 时段外收到知识
- **WHEN** 用户在 14:00 发来一条知识文本
- **THEN** 系统将其存入待处理队列并结束本次处理，不调用大模型

#### Scenario: 时段内收到知识
- **WHEN** 用户在 20:00 发来一条知识文本
- **THEN** 系统将其存入待处理队列，并在当前时段内处理

#### Scenario: 队列持久化
- **WHEN** 服务在队列非空时重启
- **THEN** 未处理的知识条目仍然存在，不会丢失

### Requirement: 大模型调用时段限制

系统 MUST 仅在每日 18:00 至次日 09:00 之间调用大模型接口，MUST NOT 在 09:00 至 18:00 之间发起任何大模型调用。

#### Scenario: 白天不调用大模型
- **WHEN** 当前时间为 14:00 且队列中有待处理知识
- **THEN** 系统不调用大模型，条目保留在队列中

#### Scenario: 跨午夜窗口判定
- **WHEN** 当前时间为次日 07:00
- **THEN** 系统判定当前处于允许时段内，可处理队列

#### Scenario: 时段开启后清空积压
- **WHEN** 时间到达 18:00 且队列中积压了白天收集的多条知识
- **THEN** 系统按入队顺序逐条处理

#### Scenario: 队列为空时不调用
- **WHEN** 当前处于允许时段但队列为空
- **THEN** 系统不发起大模型调用

### Requirement: 课程与卡片生成

系统 SHALL 调用大模型将单条原始知识文本整理为一门课程及其若干张卡片，并 MUST 以可解析的 JSON 作为模型输出格式。

#### Scenario: 生成成功
- **WHEN** 系统处理一条知识文本
- **THEN** 得到一门含标题与卡片列表的课程，每张卡片含问题与答案

#### Scenario: 模型输出不可解析
- **WHEN** 模型返回的内容不是合法 JSON 或不符合约定结构
- **THEN** 该次处理判定为失败，条目保留在队列中以待重试

### Requirement: 课程与卡片的内容结构

课程 SHALL 包含标题、原始知识文本、创建时间与卡片列表。卡片 SHALL 包含问题、答案与复习状态字段。

#### Scenario: 课程保留来源
- **WHEN** 一门课程生成完成
- **THEN** 其中保留着用户最初发送的原始文本，可用于溯源

#### Scenario: 卡片携带复习状态
- **WHEN** 卡片首次生成
- **THEN** 卡片带有初始复习状态，可直接进入复习调度

### Requirement: 持久化到 JSON 文件

系统 SHALL 将课程与卡片写入服务器本地 JSON 文件，且 MUST 在进程重启后完整恢复全部数据。

#### Scenario: 重启后数据完好
- **WHEN** 服务写入课程后重启进程
- **THEN** 已写入的课程与卡片全部可读，内容不变

#### Scenario: 写入不破坏既有数据
- **WHEN** 新课程写入时文件中已存在其他课程
- **THEN** 既有课程内容保持不变

### Requirement: 处理失败的重试

系统 SHALL 在处理失败时保留该条目并记录失败原因，MUST 在下一次允许时段重新尝试。

#### Scenario: 失败后重试
- **WHEN** 某条目在夜间处理失败（模型报错、网络中断等）
- **THEN** 该条目保留在队列中，并在下一个允许时段被再次处理

#### Scenario: 失败不产生半成品
- **WHEN** 一次处理在生成中途失败
- **THEN** 不写入不完整的课程到 JSON 文件
