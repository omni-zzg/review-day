# Spec Delta

## Purpose

飞书自建应用机器人的收发通道：以 WebSocket 长连接接收用户发来的知识消息，并支持随时主动推送消息。它是系统与用户之间唯一的即时通信界面，本身不含任何业务逻辑。

## ADDED Requirements

### Requirement: 长连接接入

系统 SHALL 通过飞书 WebSocket 长连接接收事件，MUST NOT 依赖公网 IP、域名或回调地址。

#### Scenario: 启动后建立连接
- **WHEN** 服务进程启动且凭据有效
- **THEN** 系统与飞书建立长连接并开始接收事件

#### Scenario: 连接断开后恢复
- **WHEN** 长连接因网络波动中断
- **THEN** 系统自动重连并恢复接收事件，无需人工干预

#### Scenario: 凭据无效
- **WHEN** 飞书 App ID 或 App Secret 缺失或错误
- **THEN** 系统启动失败并在日志中给出明确的凭据错误，不静默运行

### Requirement: 接收知识文本

系统 SHALL 接收用户在飞书中发给机器人的文本消息，并转交知识摄取流程。非文本消息 MUST 被忽略。

#### Scenario: 收到文本消息
- **WHEN** 用户向机器人发送一条文本消息
- **THEN** 系统接收该消息并将其作为一条原始知识转交摄取流程

#### Scenario: 收到非文本消息
- **WHEN** 用户向机器人发送图片、文件或表情
- **THEN** 系统忽略该消息，不产生待处理知识

### Requirement: 收到即回执

系统 SHALL 在收到知识文本后立即回复确认，且 MUST 在 3 秒内完成响应，以免触发飞书的事件重推。

#### Scenario: 回执内容
- **WHEN** 用户发送一条知识文本
- **THEN** 系统回复一条确认消息，告知已收到并将在夜间处理

#### Scenario: 响应超时保护
- **WHEN** 后续处理耗时超过 3 秒
- **THEN** 回执仍已在 3 秒内发出，事件处理本身不阻塞回执

### Requirement: 主动推送消息

系统 SHALL 支持在任意时刻主动向指定用户推送消息，不受时间窗口限制。

#### Scenario: 主动推送到指定用户
- **WHEN** 系统需要通知用户（例如复习提醒）
- **THEN** 系统通过飞书接口向该用户发送消息，无需用户先发消息激活会话

#### Scenario: 推送失败可感知
- **WHEN** 主动推送因权限、可用范围或网络原因失败
- **THEN** 系统记录失败原因到日志，MUST NOT 将失败当作成功
