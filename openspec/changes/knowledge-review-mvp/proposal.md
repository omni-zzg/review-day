# Proposal: knowledge-review-mvp

## Why

日常学习中收集到的知识点，散落在聊天记录、笔记、收藏夹里，事后几乎不会回看，更不会主动复习 —— **"收集"这个动作本身并不带来记忆**。本系统要补的是从"收集"到"记住"之间缺失的那一环：把随手发来的知识自动整理成课程与卡片，并按遗忘规律持续把该复习的内容推回眼前。

现在做的可行性来自两点：飞书自建应用机器人支持 **WebSocket 长连接**接收事件，不需要公网 IP、域名或内网穿透；且其**主动推送无时间窗口限制**（对比微信 ClawBot 的 context_token 约 24 小时失效且静默丢弃）。个人开发者可以零基础设施门槛搭起一条稳定的消息通道。

## What Changes

- **飞书通道**：新增飞书自建应用机器人接入。以 WebSocket 长连接接收消息，全天接收用户发来的知识文本
- **知识摄取**：新增待处理队列。原始文本入队后，**仅在 18:00–09:00 时段**调用 DeepSeek，整理为「课程 + 卡片」结构化数据，写入服务器本地 JSON 文件
- **复习调度**：新增固定间隔表驱动的复习（1 / 2 / 4 / 7 / 15 / 30 天），卡片按「记住了 / 没记住」推进下一阶段或重置回起点
- **每日提醒**：新增 07:30 / 18:30 / 21:00 三个提醒时刻，通过飞书告知当日待复习数量（**0 张也告知，但一天只告知一次**）；当日队列清空后，后续时刻不再提醒
- **Web 应用**：新增「今日复习」页（核心）与课程、卡片浏览页
- **部署形态**：单台云服务器上的单个 Node 进程，pm2 常驻，全部状态为本地 JSON 文件

## Capabilities

### New Capabilities

- `feishu-channel`: 飞书自建应用的收发通道 —— 长连接接入、接收用户发来的知识文本、向外推送提醒消息
- `knowledge-ingestion`: 知识摄取与课程生成 —— 待处理队列、大模型调用时段约束、原始文本到课程与卡片的结构化转换、JSON 持久化
- `review-scheduling`: 复习调度 —— 间隔推进规则、每日到期卡片挑选、复习记录、当日完成判定
- `review-reminder`: 复习提醒 —— 每日三个提醒时刻、提醒内容生成、已完成或无需复习时的抑制规则
- `web-app`: Web 界面 —— 今日复习页、课程与卡片浏览页

### Modified Capabilities

无。本项目为全新项目，`openspec/specs/` 下尚无既有能力。

## Impact

- **新增外部依赖**：飞书开放平台（企业自建应用，需 `im:message` 与 `im:message:send_as_bot` 权限）、DeepSeek API
- **新增运行环境**：一台公网可达的云服务器，需持久磁盘存放 JSON 数据
- **新增密钥**：飞书 App ID / App Secret、DeepSeek API Key —— 一律经 `.env` 注入并列入 `.gitignore`，严禁入库（见 `AGENTS.md`）
- **部署拓扑**：长连接是**出站**连接，收消息无需公网 IP；但 Web 界面需被手机访问，故仍需一台带公网地址的服务器
- **数据存储**：全部状态存于服务器本地 JSON 文件，不引入数据库
- **已确认不做的**：多用户、微信通道、卡片富媒体（图片/音频）、课程与卡片的手工编辑、统计图表 —— 留待后续变更
